# Security

Do not publish credentials, user data, or exploit details in a public issue. Report suspected vulnerabilities through the repository’s GitHub private vulnerability reporting feature when available, or contact an organization maintainer privately.

For self-hosting, complete first-run account setup on loopback before public exposure (the first sign-up becomes the owner), use an HTTPS reverse proxy, and protect the data volume and environment configuration. Keep PostgreSQL on a private network with its own credentials, and back it up with the matching session secret. Public signup closes after setup; workspace invitations are bearer links, valid for seven days and single use. Share them only with their intended recipient. The app provides copyable links rather than sending email.

Only instance operators can configure shared provider credentials or run connection tests. Project mappings and provider-operation recovery also require workspace administration. Saved credentials use authenticated AES-256-GCM encryption with a key derived from the instance session secret. Back up the database together with the exact configured `SESSION_SECRET`, or the generated `data/session-secret`. Losing or replacing that secret makes saved integration settings unreadable. Encryption does not replace access controls on the running host or its backups.

Blank secret inputs keep existing values. Explicitly clearing a credential disables its environment fallback; resetting a provider restores server environment values. Google Drive and Calendar share the same service account. Settings saves do not make provider requests. Connection tests make explicit metadata/authentication reads, with no inference, publishing, messages, uploads, calendar changes, or bookings. Read access does not establish all write permissions.

The Google Maps API key is intentionally visible in the browser. Restrict it to Maps JavaScript API and the permitted HTTP referrers; never use a server secret in its place. Maps changes require a browser reload to apply its script policy and loaded credentials. Service-account private keys and other provider secrets are excluded from settings responses.

Optional content approval binds decisions to shared content and every platform's effective caption, media and options, recipients, schedule, and referenced creative metadata. Changes invalidate approval, including changes to platform-specific DAM assets. Review decisions record their actor and time; they do not publish automatically. Local restriction checks validate the supplied media metadata; unknown metadata still requires provider verification. Publishing, scheduling and eligible retries require a successful Zernio preflight against the outgoing variants, and TikTok submissions check current creator permissions and posting consent. Provider-operation reviews require checking the actual external outcome: an applied decision retains the duplicate-action block, while a not-applied decision allows only a fresh manual attempt. Preserve the original receipts when investigating uncertain spending or delivery.

Local password changes verify the current password and revoke prior sessions. The server-only `reset-password` CLI reads account details from standard input, accepts only local password accounts, and revokes all sessions for that account. Keep passwords out of command arguments and shell history. Use the identity provider's MFA and recovery controls for OIDC accounts; invitation links do not replace existing passwords or automatically link identities by email.

The private database contains bounded post webhook payloads, Messenger contact identities, inbox notification metadata, attributed SMS bodies and attachment references, contact and SMS opt-out hashes, short-link destinations and campaign associations, website aggregates, AI prompts/results, invitation hashes, approval snapshots, and operation receipts. Installations upgraded from earlier versions may also retain legacy private inbox tables. SMS history and legacy records remain for operator-managed retention instead of silently deleted. Inbox reads/replies require current project access and provider/account scope. Inbox content is excluded from the assistant's tools and context. Set suitable retention and backup access policies. Credentials and private media should not be placed in public delivery URLs. AI prompts and explicitly requested campaign/post/placement/asset context are sent to the configured OpenRouter model provider; the former inbox opt-in is rejected.

The Zernio webhook receiver verifies the raw-body HMAC-SHA256 signature, enforces a 1 MB limit, and deduplicates by event UUID and raw-body hash. Post lifecycle events update existing linked posts. Recognized Zernio inbox events retain minimized routing/identity data and local notifications; verified incoming Facebook Messenger messages create deduplicated contacts without campaign consent. Zernio message, comment and review bodies are fetched on demand. Unknown/test events are metadata-only and ignored; invalid legacy inbox payloads are scrubbed and ignored. Contact, identity, notification and event completion commit atomically. Old private records and backups remain subject to the operator's retention policy.

Twilio SMS callbacks use the standard Auth Token signature over the exact public URL and form fields, with a 64 KiB body limit and configured-account/sender checks. Project-specific incoming URLs still require an outbound account/sender/recipient match; ambiguous global callbacks retain a hashed receipt without the private body. Conflicting Message SID replays are rejected. Attributed SMS bodies are stored locally. Verified STOP requests and provider opt-out rejections retain an installation-wide phone hash, blocking campaigns and inbox replies across existing and future projects. Hashes remain private suppression data and must not be removed to bypass an opt-out. No automatic resubscribe or inferred SMS campaign consent is implemented.

Short-link creation requires project editing access. Destinations are fixed, public HTTPS URLs; credentials, private/local hosts and this app's short-link loops are rejected. Public redirects are limited to the main application host or the link's saved branded host. A branded origin additionally requires an instance operator with workspace administration and externally managed DNS/TLS; the domain challenge is not independent ownership verification. See [tracking setup](https://github.com/Ten98-IO-Company/ten98-campaign/wiki/Links-and-Tracking).

Website intake uses an exact origin allowlist, credential-free CORS, bounded bodies/rates and temporary event-ID deduplication. The public project token is not authentication: non-browser clients can forge Origin headers, and event totals are not trusted conversion proof. The browser respects Do Not Track and Global Privacy Control. The app stores day/path/event counts without visitor identifiers, cookies, IP addresses, user agents, query strings, fragments or referrers; paths and event names can still contain sensitive information if the website supplies it. Reverse-proxy logs have their own retention controls.

Cloudflare email is transactional sending only. The optional reply-to address points to an externally configured receiving mailbox/group; this app does not receive email, configure forwarding, or verify the receiving route. Connection tests do not send test email or SMS or establish live delivery acceptance.

Zernio, Twilio, Cloudflare, Google, Broadsign, and OpenRouter are independently operated external services. Their access permissions, charges, availability, and terms apply to your configured accounts. The MIT license covers this application’s source code, not those services.
